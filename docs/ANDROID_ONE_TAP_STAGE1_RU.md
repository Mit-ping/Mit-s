# Android VPN: аудит и первый этап

## Основание и границы

Аудит выполнен на базе `337794586e75b90fc0195e643b5a15a3df0f1aba`.
Запрошенных `AGENTS.md`, `docs/ONE_TAP_VPN_MVP_RU.md` и
`docs/CODEX_ANDROID_KICKOFF_RU.md` нет в checkout и в полученной `origin/main`.
После уточнения пользователь поручил самостоятельно определить первый этап.
Основание — требования в задаче; отсутствующие документы не считаются прочитанными.

Сервер Xray и нативные проекты iOS/Windows не изменяются. Пилот включается
только на Android с `--dart-define=ONE_TAP_VPN=true`; обычные сборки сохраняют
экран и настройки Hiddify. Исправление логирования URL действует на всех платформах.
Отключение Android backup действует и на обычную Android-сборку.

## Результаты аудита

* `ConnectionButton` использует реальный `ConnectionNotifier`, а не демонстрационную
  анимацию из `new_connection_button.dart`. Он показывает состояния ядра, включая
  ожидание, ошибку и отсутствие доступных прокси. Его следует переиспользовать.
* `ConnectionRepositoryImpl` применяет опции до запуска ядра; разрешения Android VPN
  и жизненный цикл службы остаются в существующем native/core коде.
* `ConfigOptions.region` по умолчанию равен `other`; региональный direct сам по себе
  не гарантирует обход РФ. Настройки профиля накладываются на пользовательские опции.
* `BuiltinRule.bypassRegion` уже поддерживает пары geosite/geoip с `{region}`,
  которые передаются ядру. Не следует изобретать второй маршрутизатор в Dart.
* `ProfileRepositoryImpl.addLocal` проверяет конфигурацию ядром перед записью
  метаданных в БД и удаляет временный файл в `finally`. Новый профиль активируется
  существующим механизмом. Пилот сохраняет этот путь и не подключается автоматически
  при импорте: подключение требует отдельного нажатия и штатного согласия Android.
* В `AddProfileNotifier.addClipboard` полный URL подписки попадал в debug-лог.
  URL может содержать токен: удалён из сообщения. Это не полный аудит всех логов
  Dart/native/core и Sentry; считать все каналы очищенными пока нельзя.
* Профили хранятся в файловой системе приложения и БД без отдельного Keystore-шифрования.
  Ранее manifest не запрещал backup. Теперь backup отключён, Android 12+ cloud backup
  и device transfer явно исключают данные приложения. Это не защита от root и не
  замена шифрованию; удаление профиля также не гарантирует физического стирания флеш-памяти.

## Реализованный этап

Пилотный домашний экран содержит существующую кнопку подключения и явный импорт
одной ссылки VLESS + REALITY/TCP. Поле скрывает ввод, отключает подсказки клавиатуры.
Проверяются UUID, порт, REALITY public key (base64url, 32 байта), SNI, fingerprint,
short ID, transport и flow. Дубликаты и неизвестные параметры, JSON, подписки,
несколько ссылок и oversized input отвергаются до обращения к ядру.
Ошибки импорта не отображают исходную ссылку или текст исключения ядра.
Поддержка дополнительных вариантов транспорта/параметров потребует отдельных тестов.

Политика применяется после overrides профиля: TUN, регион `ru`, LAN direct,
`.ru`/`.su`/`.рф` direct и российские geosite/geoip direct. Остальной трафик должен
использовать стандартный proxy outbound ядра Hiddify. Пользовательские правила
не перезаписываются на диске, но не участвуют в политике пилота. LAN sharing и
Clash API отключены в его runtime-опциях.

Это этап поверх существующего Hiddify, не готовый отдельный брендированный клиент:
остальные разделы приложения и существующие профили ещё доступны. Старый активный
профиль не мигрируется и не проверяется новым валидатором. Для проверки пилота нужна
чистая установка и импорт VLESS + REALITY через новый экран. Следующий этап должен
определить миграцию/ограничение старых профилей, управление удалением и ротацией ключей.

## Проверка и запуск

Нужны Flutter 3.38.5 / Dart 3.10.4, Android SDK/устройство и зависимости проекта.
Команды выполняются из корня существующего checkout; отдельный worktree не нужен.

```sh
flutter pub get --enforce-lockfile
dart run build_runner build --delete-conflicting-outputs
dart run slang
flutter analyze --no-fatal-infos --no-fatal-warnings
flutter test test/features/one_tap
flutter test
make android-libs
flutter run -d <android-device> --dart-define=ONE_TAP_VPN=true
```

Перед генерацией сохранить пользовательские изменения и проверить diff после неё.
Нативная библиотека берётся штатным Makefile из Hiddify core; сервер Xray не меняется.
Не помещать реальные ссылки, UUID пользователей или ключи в команды shell/логи/PR.
Ссылка вводится локально на устройстве через экран импорта.

Добавлены unit-тесты валидатора и runtime-политики и widget-тесты отказа от подписки
и блокировки импорта во время подключения. Тестовые адреса/UUID/ключ синтетические.

В текущей облачной машине запуск Flutter блокируется скачиванием Dart SDK:
`storage.googleapis.com` отклонён прокси (CONNECT 403). Проверки перенесены в
GitHub Actions: генерация, анализ и новые Dart-тесты пилота прошли
[в этом запуске](https://github.com/Mit-ping/Mit-s/actions/runs/41051230578).
Полный набор блокировали шесть ошибок миграционных тестов на SQLite 3.37.2
в строгом режиме Drift. Причина воспроизведена отдельно; CI переведён на Ubuntu
24.04 с более новой SQLite и проверкой строгого режима перед тестами.
APK и реальный туннель ещё не проверены. Проверка XML, `git diff --check` и
существующий Python-валидатор конфигурации iOS прошли. Этот этап нельзя считать
проверенным рабочим Android-клиентом до сборки и проверки на устройстве.

Обязательный device smoke test до выпуска: согласие/отказ VPN permission; connect,
disconnect, повторный connect; отмена подключения; ошибочная REALITY-конфигурация;
проверка direct для РФ и proxy для зарубежных адресов по фактическому egress;
DNS и IPv6; недоступность rule-set; переключение Wi-Fi/сотовой сети; перезапуск
приложения; отсутствие ключей в logcat/экспорте логов/backup. Успешный статус кнопки
сам по себе не доказывает корректную маршрутизацию и отсутствие утечек.
