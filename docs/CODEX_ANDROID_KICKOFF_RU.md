# Первое задание Codex: Android one-tap VPN

Работай в ветке `feature/android-one-tap-mvp`. Прочитай `AGENTS.md` и `docs/ONE_TAP_VPN_MVP_RU.md` прежде, чем менять код.

## Шаг 1. Аудит кода
Найди и перечисли реальные пути:
- Flutter entrypoints, routing/navigation, домашняя страница;
- provider/state для VPN подключения/отключения;
- загрузка и хранение subscription/profile;
- сборка конфигурации sing-box, DNS и route rules;
- Android VPN/TUN integration, lifecycle, permission handling;
- существующие Android CI build jobs/tests.

Не придумывай имена файлов, а указывай существующие пути. Если компонент отсутствует — отметь.

## Шаг 2. Небольшой работоспособный вертикальный срез
Реализуй упрощённый русскоязычный Android главный экран (подключение/отключение), используя текущую платформенную реализацию VPN и состояние из существующих providers. Добавь корректные состояния: idle, connecting, connected, disconnecting, error. Показывай первичную настройку при отсутствии профиля; **не симулируй VPN**. Сохрани диагностику/импорт конфигурации доступными из дополнительного меню.

По возможности пока НЕ изменяй код Windows/iOS. Не занимайся ребрендингом всех файлов пакета в первом PR. Не добавляй реальные server/IP/UUID/REALITY параметры, токены или URL подписок в исходники. Split routing разрабатывать отдельно, на базе существующего config builder и sing-box rule sets; сначала дай план с тестами и минимальный реалистичный конфиг для test fixture без живых ключей.

## Шаг 3. Проверки
Выполни `flutter analyze`, подходящие Flutter tests и Android debug build (если среда позволяет). Если не хватает toolchain или зависимостей, укажи точную команду для локального/CI запуска; не утверждай, что сборка успешна. Добавь тесты для состояний UI, если реалистично, и пошаговый ручной тест Android подключения.

## Итог
В pull request укажи изменённые файлы, выполненные команды, непройденные проверки и следующий этап. Сохрани upstream лицензии.
