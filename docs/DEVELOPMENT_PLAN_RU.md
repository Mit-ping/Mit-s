# План разработки Android VPN

## Правила работы

Работаем в существующем checkout и отдельной ветке, без дополнительного worktree.
После каждого этапа фиксируем изменения, реально выполненные проверки и следующий
шаг. Незавершённую проверку не считаем успешной. Сервер Xray не меняем; реальные
профили и ключи не попадают в репозиторий, CI, артефакты диагностики и PR.
Новые возможности пилота включаются только на Android; совместимость iOS и Windows
проверяется перед объединением изменений в основную ветку.

## Этапы и критерии завершения

1. **Основа и аудит.** Уточнить MVP, проверить существующее подключение, профильный
   импорт и маршрутизацию; сохранить аудит и план.
   Статус: аудит и первоначальный Android-пилот в ветке `feat/android-one-tap-pilot`.
   См. [аудит](ANDROID_ONE_TAP_STAGE1_RU.md). Запрошенные исходные kickoff-документы
   отсутствуют; пользователь поручил самостоятельно выбрать первый этап.
2. **Воспроизводимая сборка.** Получить закреплённый Flutter/Android SDK, выполнить
   codegen, анализ и тесты. Подготовить отдельную CI-сборку без production-секретов.
   Статус: workflow `Android one-tap APK` подготовлен; его выполнение ещё не подтверждено.
   Локальная сборка блокируется запретом `storage.googleapis.com`; GitHub API тоже
   недоступен. Черновик сетевых разрешений сохранён, но ещё не применён к машине.
3. **Первый скачиваемый APK.** После успешных анализа, тестов и сборки получить
   `one-tap-vpn-debug.apk` и SHA-256, проверить установку на Android.
   Статус: не выполнен; наличие workflow не означает наличие APK.
4. **Проверка настоящего VPN.** На устройстве проверить permission, connect/disconnect,
   отмену, ошибки REALITY, поведение при смене сети и восстановлении приложения.
   Проверить фактический egress российских и зарубежных адресов, DNS и IPv6.
   Подтвердить, что недоступность rule-set не создаёт незаметного обхода политики.
   Статус: не выполнен; требуется устройство и профиль, вводимый локально.
5. **Дизайн.** Выбрать название, цвета, типографику; согласовать макеты домашнего экрана,
   импорта и управления профилями, состояний подключения и ошибок. Макеты можно
   обсуждать параллельно, внедрение — после проверки базового туннеля.
   Статус: не начат; текущий экран — техническая заготовка.
6. **Реализация дизайна.** Перенести утверждённые экраны, определить миграцию старых
   профилей и убрать лишние пути Android-интерфейса, не меняя другие платформы.
   Повторить функциональные тесты; выпустить новый тестовый APK.
7. **Версия для использования.** Доработать защиту профилей и логов, стабильность,
   accessibility, обновления и подпись. Проверить совместимость и подготовить
   подписанный APK с инструкцией установки. Production-ключ хранится вне Git.

## Как получить APK через GitHub Actions

Workflow `.github/workflows/android-one-tap.yml` запускается при push в ветки
`feat/android-one-tap-*`. Для него не нужны production signing secrets и он
не публикует релизы. Все проверки должны пройти до загрузки APK-артефакта.

1. В репозитории открыть **Actions → Android one-tap APK**.
2. Выбрать успешный запуск с нужным коммитом ветки.
3. Скачать artifact `one-tap-vpn-debug-<полный SHA>` и распаковать ZIP.
4. Проверить `SHA256SUMS` и установить `one-tap-vpn-debug.apk` на тестовое устройство.

Это debug-сборка с временной подписью и существующим application ID Hiddify.
Она может конфликтовать с установленным Hiddify по подписи. Использовать чистое
тестовое устройство/эмулятор или отдельный Android-профиль; не удалять рабочий
Hiddify без безопасного сохранения его профилей. Подпись может меняться между
CI-запусками, поэтому обновление поверх предыдущего тестового APK не гарантируется.
Стабильная идентичность нашего приложения и release-подпись — отдельная задача
до распространения. Debug APK не предназначен для постоянного использования.

## Формат отчёта об итерации

* Сделано.
* Проверено (с отдельно указанными ошибками и незапущенными проверками).
* Что можно посмотреть или скачать.
* Следующий шаг и конкретный внешний блокер, если он есть.
