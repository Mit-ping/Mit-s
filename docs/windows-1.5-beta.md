# Mit's VPN для Windows — 1.5.0-beta.4

Перенесён функционал телефонной Beta 1.5 из коммита `05cff740`:
одна кнопка, VLESS/REALITY, AmneziaWG, импорт файлов, управление профилями,
резервные профили, автоматическое восстановление, безопасный отчёт.

Windows-адаптации: импорт QR из изображения, состояние сети через Windows NLM,
автозапуск приложения, обновления через отдельный EXE с проверкой размера и SHA256.
При закрытии приложения автовосстановление прекращается. Android Always-on VPN
и системная блокировка после остановки службы не выдаются за функции Windows.
В Windows используется TUN со строгой маршрутизацией во время подключения.

Названия приложения, EXE, установщика, ярлыков и изображения заменены на Mit's VPN.
Установщик использует собственный идентификатор Mit's VPN, чтобы не наследовать
имя и папку установки исходного приложения.
Служебные имена и бинарные компоненты стороннего VPN-ядра, а также обязательная
атрибуция в лицензии сохранены. Данные предыдущей Windows-сборки копируются
в новый каталог при первом запуске, если он пуст; оригинал остаётся на месте.
Перед переносом необходимо закрыть старую версию. Каталог portable-данных
переименовывается в `mits_vpn_data` с сохранением содержимого.

Сборка запускается push в ветку `build/windows-1.5-beta`, без GitHub Release.
[Workflow](../.github/workflows/windows-build.yml) создаёт артефакт
`MitsVPN-1.5.0-beta.4-Windows-x64`:

- `MitsVPN-1.5.0-beta.4-Windows-x64-Setup.exe`;
- `MitsVPN-1.5.0-beta.4-Windows-x64-Portable.zip`;
- манифест Windows-обновления, SHA256SUMS и снимок окна приложения.

Нативный тест AWG обязателен. Windows-тесты используют каталог
`MIT_NATIVE_TEST_DIRECTORY`; после завершения всех тестовых процессов родительский
шаг удаляет этот каталог, поскольку нативный логгер удерживает файлы до выхода процесса. Он проверяет реальные ответы ядра и сохранение
параметров обфускации. Проверка portable ZIP проверяет метаданные продукта,
появление окна и отсутствие немедленного завершения приложения.
Сборка и тесты не заменяют проверку подключения к вашему VPN-серверу.

Установщик без цифровой подписи может вызвать предупреждение SmartScreen.
MSIX требует отдельной настройки подписи и в эту сборку не входит.
Номер 1.5 ниже исходной версии 5.0: установка MSIX поверх 5.0 не поддерживается.

## Обновления

Опубликованный вручную выпуск `mit-windows-1.5.0-beta.4` должен содержать
`mits-vpn-windows-update.json` и EXE с точным именем из этого манифеста.
Пока релиз не опубликован, страница обновлений не предлагает сборку из Actions.
Манифест Android и APK в Windows не используются. Установщик открывается
только после отдельного подтверждения пользователя; подпись текущей беты
не объявляется проверенной.

## Закреплённое ядро

Архив `vendor/windows/vpn-core.tar.gz` пересобран из точного исходного коммита
`2abb184510f62ce0fdc16712b9052bf1f18d272a` с исправлениями службы Windows.
Происхождение, SHA256, build ID и ссылка на сборку сохранены в
`vendor/windows/core-manifest.json`. Полный diff и версии подмодулей включены;
перед распаковкой SHA256 проверяется. Зависимости сохраняют исходные версии.
Сведения об исходном проекте сохранены в лицензии и NOTICE.

## Исправление запуска в Beta 1.5.0-beta.3

Параметр `executable_name: MitsVPN.exe` обязателен: по умолчанию fastforge выбирает
первый EXE в папке, которым может оказаться служебная программа без интерфейса.
Ярлыки явно задают основной EXE, его иконку и рабочий каталог. Повторная установка
исправляет ранее созданные ярлыки. Идентификатор установщика не изменён.

Windows-проверка запускает настоящий установщик, проверяет цели ярлыков,
открывает установленное приложение напрямую и через ярлык из посторонней
рабочей папки, а затем проверяет восстановление старого неверного ярлыка
переустановкой. В конце выполняется удаление тестовой установки.

## Исправление подключения в Beta 1.5.0-beta.4

В исходном ядре права `control.secret` задавались через английское имя
`BUILTIN\Administrators`. При локализованном имени группы установка службы
завершалась ошибкой Windows «No mapping between account names and security IDs
was done», даже после подтверждения UAC. Дефект воспроизведён в Actions:
исходное ядро проходит тест трафика с английским именем группы и не устанавливает
службу после её переименования в русское имя.

Патчи в `vendor/windows/patches` используют SID исходного пользователя и
общеизвестные SID SYSTEM/Administrators, защищают DACL от наследования и
отказывают при невозможности разрешить пользователя. Приложение передаёт
имя с доменом Windows. CLI возвращает ненулевой код при ошибке подключения;
до исправления он сообщал успех даже при отклонённом профиле.

Проверка `smoke_test_vpn_service.ps1` устанавливает службу через настоящий
административный EXE, проверяет SID в ACL, отказ для нерабочего профиля,
создание TUN и передачу HTTP-трафика через TUN и прокси. Используются локальный
тестовый прокси и зарезервированный диапазон 198.18.0.0/15. Доступ к серверу
пользователя и его ключи не нужны. Тест с русским именем системной группы
выполняется только на временном Windows runner; исходное имя восстанавливается.

Окно ошибки показывает этап и постоянный код WIN-VPN, без содержимого профиля.
Перед показом успешного подключения приложение проверяет доступ к API службы.
