## Разбор обращения

Пользователь сообщил, что клиентская ссылка vpn:// из AmneziaVPN со своего сервера
отклоняется до добавления профиля. По префиксу ссылки протокол и конкретные поля
определить нельзя; полный ключ не запрашивался. Его содержание не воспроизводилось
в тестах. Показанная ошибка была слишком общей.

Достоверно найдены ограничения реализации: picker разрешал только conf/txt;
на Android MIME-фильтрация отключала выбор .vpn; импортер требовал единственный
контейнер и непустой INI в last_config.config. Не поддерживались отдельные
клиентские поля и пустые необязательные параметры.

В Alpha 1.1 picker использует FileType.any с проверкой расширения после выбора.
Файлы .vpn могут содержать URL, JSON Amnezia, Base64URL или Qt-compressed bytes;
все варианты проходят тот же ограниченный валидатор, что и вставка ссылки.
Известные пустые необязательные поля пропускаются; обязательные/неизвестные поля,
дубли, команды, неоднозначные AWG-профили и admin credentials по-прежнему отклоняются.
Параметры маскировки дополняются из client/server metadata, если их нет в INI;
явное непустое значение в INI имеет приоритет. SSH-порт не используется как VPN-порт.

Добавлены синтетические regression-тесты форматов, picker API, расширений,
очистки временных копий, native AWG RPC и отображения версии. Реальные ключи
не сохраняются в репозитории и не включаются в отчёты.

Диагностические коды: AWG-01 — распаковка/неполный ключ; AWG-02 — нет однозначного
AWG-контейнера; AWG-03 — неполная клиентская часть; AWG-04 — параметры INI;
FILE-01 — чтение/тип/размер выбранного файла. Коды фиксированные, без данных профиля.
